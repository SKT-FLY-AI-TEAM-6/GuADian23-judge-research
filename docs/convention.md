### Part 01. 작업 흐름

| 순서 | 단계 | 규칙 | 예시 |
| :-: | :-- | :-- | :-- |
| 1 | 이슈 | 모든 작업은 이슈부터 | `[Feat] 광고 테두리 오버레이 표시` ⇒ #12 |
| 2 | 브랜치 | `main`에서 분기 · 이슈 1개당 브랜치 1개 | `feat/ad-border-overlay` |
| 3 | 커밋 | 커밋 1개당 변경 1가지 · 제목 끝에 `(#이슈번호)` | `feat(app): 광고 테두리 오버레이 표시 (#12)` |
| 4 | PR | 제목은 커밋과 동일 규칙 · 본문에 `Closes #12` | `feat(app): 광고 테두리 오버레이 표시 (#12)` |
| 5 | 리뷰 | 1명 이상 승인 | `P1:` 필수 · `P2:` 권장 · `P3:` 선택 · `Q:` 질문 |
| 6 | 머지 | **Squash and merge** · 작성자 본인이 머지 · 브랜치 삭제 | `main`에 PR 1개당 커밋 1개 |

이슈 번호 **#12** 하나로 전 과정 연결 — `#12`는 GitHub 자동 링크, `Closes #12`는 머지 시 이슈 자동 닫힘

| 위치 | 번호 자리 | 예시 |
| :-- | :-- | :-- |
| 이슈 | 생성 시 자동 부여 | #12 |
| 커밋 | 제목 **끝** `(#12)` | `feat(app): 광고 테두리 오버레이 표시 (#12)` |
| PR | 제목 끝 `(#12)` + 본문 `Closes #12` | `feat(app): 광고 테두리 오버레이 표시 (#12)` |
| `main` | Squash 시 PR 번호 자동 추가 | `feat(app): 광고 테두리 오버레이 표시 (#12) (#15)` |

대소문자 — 이슈 제목의 `[Feat]`만 첫 글자 대문자, 나머지는 전부 **소문자**

| 위치 | 대소문자 | 예시 |
| :-- | :-- | :-- |
| 이슈 제목 | `[Feat]` 첫 글자 대문자 · 내용은 한글 | `[Feat] 광고 테두리 오버레이 표시` |
| 브랜치 | 전부 소문자 · 하이픈 | `feat/ad-border-overlay` |
| 커밋 · PR 제목 | `feat(app):` 타입 · 스코프 소문자 · 영어 내용은 소문자 시작 | `feat(app): 광고 테두리 오버레이 표시 (#12)` · `fix(server): add domain to cache key (#27)` |
| 고유명사 | 원래 표기 그대로 | `README` · `FCM` · `JDK 17` · `Gradle` · `judge_agent` |
| 리뷰 접두어 | 대문자 | `P1:` `P2:` `P3:` `Q:` |

### Part 02. 이슈 · 브랜치

| 타입 | 이슈 제목 | 브랜치 | 용도 |
| :-: | :-- | :-- | :-- |
| Feat | `[Feat] 광고 테두리 오버레이 표시` | `feat/ad-border-overlay` | 새 기능 |
| Fix | `[Fix] 앱 재시작 시 FCM 토큰 유실` | `fix/fcm-token-refresh` | 버그 |
| Refactor | `[Refactor] 프리페치 judge_agent 이동` | `refactor/judge-prefetch` | 구조 개선 |
| Docs | `[Docs] README JDK 17 명시` | `docs/readme-jdk` | 문서 |
| Chore | `[Chore] Gradle 8.7 고정` | `chore/gradle-8-7` | 빌드 · 설정 |

| 번호 | 규칙 |
| :-: | :-- |
| 1 | 이슈 제목은 **명사형** — `~ 표시` `~ 수정` · `~했어요` ✗ |
| 2 | 브랜치는 `타입/설명` — 소문자 · 하이픈 · **영어** · 이슈 번호 없음 |
| 3 | `main` 직접 push 금지 · `main` 반영은 `git rebase origin/main` |

### Part 03. 커밋

```
타입(스코프): 제목 (#이슈번호)   50자 이내 · 마침표 없음 · 명사형

본문 (선택)                   변경 이유 · 달라지는 동작
```

| 타입 | feat · fix · refactor · style · test · docs · build · chore |
| :-- | :-- |
| **스코프** | `app` · `server` · `firebase` · `docs` · `build` · 생략 = 전체 |

| 판정 | 예시 | 비고 |
| :-: | :-- | :-- |
| O | `feat(server): 판정 결과 24시간 캐시 (#20)` | |
| O | `fix(app): 오버레이 권한 없을 때 크래시 수정 (#27)` | |
| O | `docs: README Quick Start에 JDK 17 명시 (#8)` | |
| X | `Add files via upload` | 타입 · 내용 없음 |
| X | `feat(app): 광고 테두리 오버레이 표시` | 이슈 번호 없음 |
| X | `feat(app): 광고 표시 + 서버 캐시 + README 수정 (#12)` | 3개로 분리 |
| X | `feat(app): 광고 표시 기능을 추가했습니다.` | 마침표 · 서술형 |

### Part 04. PR · 리뷰

| 항목 | 규칙 |
| :-- | :-- |
| 제목 | 커밋 제목과 **동일 규칙** · 끝에 `(#이슈번호)` — Squash 머지 시 `main` 커밋 메시지 |
| 본문 | [양식](#part-05-양식)대로 · `Closes #n` 필수 · UI 변경은 Before / After 스크린샷 |
| 크기 | **300줄 이내** · 리팩터와 기능 추가 분리 |
| 올리기 전 | 본인 diff 전체 확인 — 디버그 로그 · 주석 코드 · 비밀 값 (`google-services.json` · API 키) 제거 |
| 리뷰어 | 요청 후 **24시간 내** 첫 반응 · 지적 시 대안 제시 |
| 작성자 | 모든 코멘트에 답변 · 반영 커밋은 추가 (리뷰 중 force push ✗) · 완료 후 Re-request review |
| 머지 | 승인 1명 이상 · **Squash and merge** · **작성자 본인**이 머지 |

| 접두어 | 의미 | 반영 |
| :-: | :-- | :-: |
| `P1:` | 머지 전 필수 수정 — 버그 · 보안 | 필수 |
| `P2:` | 수정 권장 — 사유 있으면 미반영 가능 | 답변 |
| `P3:` | 취향 · 사소한 사항 | 선택 |
| `Q:` | 질문 — 수정 요청 아님 | 답변 |

### Part 05. 양식

`.github/ISSUE_TEMPLATE/` · `.github/PULL_REQUEST_TEMPLATE.md` 배치 시 자동 적용

| 번호 | 양식 | 핵심 |
| :-: | :-- | :-- |
| 1 | [이슈 · 기능](#1-이슈--기능) | 대상 화면 · 기능 → 작업 내용 → 변경 예정 파일 → 완료 조건 |
| 2 | [이슈 · 버그](#2-이슈--버그) | 재현 방법 → 기대 / 실제 → 환경 → 추정 원인 |
| 3 | [PR](#3-pr) | 관련 이슈 → 작업 내용 → 파일별 변경 사항 → 테스트 방법 |

#### 1. 이슈 · 기능

```markdown
### 어떤 기능
- 화면: <!-- figma.md 번호 -->
- 기능: <!-- spec.md 번호 -->
- 사용자: <!-- 어르신 / 보호자 -->

### 작업 내용
<!-- 무엇을 · 왜 -->
-

### 변경 예정
<!-- 미정이면 공란 · PR에서 작성 -->
| 영역 | 파일 | 내용 |
| :-- | :-- | :-- |
|  |  |  |

### 완료 조건
- [ ]
```

#### 2. 이슈 · 버그

```markdown
### 현상
<!-- 한 줄로 -->

### 재현 방법
1.
2.

### 기대 / 실제
- 기대:
- 실제: <!-- 스크린샷 · 로그 -->

### 환경
- 영역: <!-- app / server / firebase -->
- 화면: <!-- figma.md 번호 -->
- 기기 · OS:
- 브랜치 · 커밋:

### 추정 원인
<!-- 미정이면 공란 -->
| 영역 | 파일 | 의심 지점 |
| :-- | :-- | :-- |
|  |  |  |
```

#### 3. PR

```markdown
### 관련 이슈
Closes #

### 작업 내용
<!-- 무엇을 · 왜 -->
-

### 변경 사항
| 영역 | 파일 | 내용 |
| :-- | :-- | :-- |
|  |  |  |

### 테스트 방법
<!-- 리뷰어가 그대로 재현 가능한 수준 -->
- 빌드:
- 기기:
- 순서:
  1.
  2.

### 스크린샷
<!-- UI 변경 시 · Before / After -->

### 리뷰 포인트
<!-- 없으면 "없음" -->
```
