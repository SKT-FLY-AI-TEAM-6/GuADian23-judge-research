### 1. 판정 흐름

`/judge` 요청 한 건의 처리 순서. 판정 기준은 룰 엔진이 아니라 프롬프트(`CRITERIA`) — 정상 쇼핑몰도 카드번호를 받아 신호는 같고 맥락만 다르므로, 맥락 판단은 LLM · 강제는 코드(근거 검증) 담당

| 순서 | 단계 | 내용 | 적중·결과 |
| :-: | :-- | :-- | :-- |
| 0 | 차단 목록 | ut1 phishing + malware 26만+ 도메인 · SQLite 조회 0.14ms · 하루 1회 갱신 · 하위 도메인 포함 | 즉시 `HIGH` — 페이지 열기·Claude 호출 없음 |
| 1 | 광고 식별키 | 클릭 주소에서 휘발성 파라미터(gclid·utm 등) 제거한 키로 이전 판정 조회 | 캐시 재사용 |
| 2 | 광고주 사이트 | 등록 도메인 단위 캐시 (메모리 → DB) | 캐시 재사용 |
| 3 | 미리 모으기 | 페이지 본문(HTTP 리다이렉트 끝까지 · JS/meta 3홉) · 페이지 신호(폼·APK 링크·브랜드 불일치) · 차단 목록 · 전 판정 · 공식 도메인(조건부: 본문 못 읽음·oneshot 브랜드 언급) · 도메인 등록일(RDAP)을 병렬 수집 (≤4.5s) | 첫 질문에 전부 포함 |
| 4 | Claude 판정 | `claude-haiku-4-5` · 왕복 1회(oneshot) 기본 · `final_verdict` 도구 스키마로만 수신 — 임의 등급·유형 생성 불가 | `LOW`/`MEDIUM`/`HIGH` + 유형 |
| 5 | 근거 검증 | `_ground` — 고위험 evidence가 도구 결과 원문에 실재하지 않으면 강등 | `HIGH` → `MEDIUM` |

시간 예산: 미리 모으기 ≤4.5s → 전체 7.5s → 하드 리밋 9.0s (초과 시 `UNKNOWN` 응답) → 앱 쉴드 12s (무응답 시 앱이 확인 불가 화면)

### 2. 위험 등급 기준

| 등급 | 조건 | 앱 개입 |
| :-: | :-- | :-- |
| `HIGH` | **확실할 때만** — 선택권을 빼앗는 판정 · ① 브랜드 자처 + 도메인 불일치(사칭) ② 정체불명·사칭 맥락의 비밀번호·주민번호·카드번호 요구 (공식 확인된 로그인·결제 제외) ③ 스토어 밖 APK 직접 다운로드 | "돌아가기"만 |
| `MEDIUM` | 개인정보 입력 폼(**공식 브랜드여도** — 뜻은 "사기"가 아니라 "넣기 전 확인" · 예외: 공식 확인된 로그인·회원가입 폼은 `LOW`) · 사업자 정보 없는 결제·가입 유도 · 당첨·무료·한정 유도 · 투자·고수익·부업 권유 · 콘텐츠팜 · **페이지 확인 불가** | "돌아가기" / "그래도 보기" |
| `LOW` | 내용을 실제로 확인 + 위 해당 없음 · 평범한 쇼핑몰·기사·회사 소개 | 쉴드 해제 |
| `UNKNOWN` | 판정 자체 실패 (시간 초과 · LLM 장애) — 사이트의 성질이 아니므로 기록만 남고 **캐시 재사용 없음** | "돌아가기" / "그래도 보기" |

저위험 예외 둘 (전제: 공식 도메인 표 `BRANDS` 약 80개에서 확인): ① 본문을 못 읽었어도(JS 렌더링 · 403) 도착 도메인이 공식이면 `LOW` — 공식 도메인은 사칭 불가능한 근거 + 큰 회사일수록 본문을 JS로 그림. 예외가 없으면 제대로 만든 사이트일수록 경고가 뜨고 어르신이 경고에 무뎌짐. ② 공식 사이트의 로그인·회원가입 폼은 `LOW` — 계정은 본인이 의도한 행동, 사칭 가설은 공식 확인으로 소거. 전화번호 수집형 폼(상담·응모·견적)은 공식이어도 `MEDIUM` 유지 (2026-08-24 기준 변경). 단 도메인 등록일만으로는 저위험 불가(오래된 도메인도 사고팔림)

**신원 × 행동 판정표** — 위 등급 기준 + 저위험 예외 둘의 전개. 규칙이 표에 앞섬(기준 변경 시 표도 갱신)

| 신원 ↓ · 행동 → | 열람만 | 로그인·회원가입 | 연락처 수집¹ | 결제·가입 | 주민번호·카드 요구 | APK 설치 |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: |
| 악성 목록 등재 (단계 0) | HIGH | HIGH | HIGH | HIGH | HIGH | HIGH |
| 사칭 확정 (브랜드 자처 + 도메인 불일치) | HIGH | HIGH | HIGH | HIGH | HIGH | HIGH |
| 공식 확인 (`BRANDS` 일치) | LOW | LOW | MEDIUM¹ | LOW | LOW (본인인증·정상 결제) | MEDIUM² |
| 정체 불명 (본문 읽힘 · 표 밖) | LOW | MEDIUM | MEDIUM | 사업자 있음 LOW · 없음 MEDIUM | HIGH | HIGH |
| 확인 불가 (본문 못 읽음) | 표에 있으면 LOW · 없으면 MEDIUM(`unverifiable`) — 본문 없이는 행동 판별 불가, 열 구분 없음 | | | | | |

행별 판별 기준:

- 악성 목록·사칭 확정: 신원만으로 판정 종료 — 목록 적중은 단계 0 즉시 HIGH(행동 판별 이전) · 사칭은 HIGH ①(도메인 불일치 = 위조 불가 근거) → 전열 동일
- 공식 확인: 공식 확인이 소거하는 건 사칭 가설뿐 — 위험이 사칭에서 오는 칸만 LOW(로그인·회원가입 = 예외 ② · 본인인증·정상 결제 = HIGH ②의 제외 조항 · 결제 = 사업자 실체 확인) · 사칭과 무관한 위험은 등급 잔존(연락처¹·APK²)
- 정체 불명: 등급 기준 직접 적용 — 표 밖 ≠ 위험 근거 · 결제는 사업자 표기가 신원의 대체 근거 · 주민번호·카드 = HIGH ② 본문 · APK = HIGH ③
- 확인 불가: 폼 존재 여부조차 미상 → 행동 축 소멸, 남는 근거는 도메인뿐(예외 ①)

¹ 공식 사이트 연락처 폼(상담·응모·견적): 등급 MEDIUM 유지 · reason은 "위험" 아닌 비용 고지형 — "공식 사이트지만 연락처를 넣으면 연락이 올 수 있어요" (프롬프트 명시, 2026-08-24)
² 공식이어도 스토어 밖 설치 위험(스토어 검증 우회)은 신원과 무관하게 잔존 — HIGH ③에서 한 단계 강등

### 3. 위험 유형 (type)

등급과 별개로 "무엇 때문에 그 등급인지" 하나 선택 — 보호자 화면 표시용. 여럿 해당 시 가장 위험한 것 하나(아래 순서 = 우선순위). `LOW`가 아니면 `none` 불가 · `LOW`면 서버가 `none`으로 정규화(`_ground`)

| type | 화면 이름 | 뜻 |
| :-- | :-- | :-- |
| `impersonation` | 사칭 | 다른 회사·기관 사칭 |
| `credentials` | 비밀번호·주민번호 요구 | 비밀번호·주민번호·카드번호 요구 |
| `apk` | 앱 파일 내려받기 | 앱스토어 밖 APK 다운로드 유도 |
| `personal_info` | 개인정보 요구 | 이름·전화번호 입력 폼 |
| `payment` | 결제 유도 | 사업자 정보 없는 결제·가입 유도 |
| `urgency` | 당첨·무료 유도 | 당첨·무료·한정 급행 유도 |
| `investment` | 투자 권유 | 투자·고수익·재테크·부업 권유 |
| `contentfarm` | 콘텐츠팜 | 미끼 링크 · 광고 가득한 출처 불명 글 |
| `unverifiable` | 확인 불가 | 페이지 확인 불가 |
| `blocklist` | 악성 목록 등재 | 차단 목록 적중 (빠른 길 0 전용) |
| `none` | (빈칸) | 저위험 · 해당 없음 |

### 4. 오탐 방지 장치

설계 원칙: **오탐 하나가 미탐 열보다 나쁨** — 정상 광고가 빨강이면 "광고는 광고일 뿐, 위험한 건 따로 있다"는 앱의 주장 붕괴. 전부 실사고에서 나온 장치

| 장치 | 내용 | 계기 (실측) |
| :-- | :-- | :-- |
| 근거 검증 (`_ground`) | 고위험 evidence가 도구 결과 원문에 없으면 `MEDIUM` 강등 · `LOW`는 type `none` 정규화 — LLM 출력에 코드가 개입하는 유일한 지점 | LLM의 지어낸 근거로 선택권 박탈 방지 |
| 차단 목록 선별 | smed79/blacklist 제외 — 목적이 "광고·추적 차단"이라 정상 서비스 포함 | ader.naver.com 빨강 (ad.daum.net · lcs.naver.com 등재 확인) |
| 공식 도메인 표 (`BRANDS`) | JS 렌더링·403으로 본문 못 읽어도 표에서 공식 확인 시 `LOW` | AXA 다이렉트 "확인 불가(중위험)" 오판 (2026-08-23) · 쿠팡 403 (2026-08-24) |
| 장터 도메인 캐시 제외 (`SHARED_SITES`) | naver.com·coupang.com 등은 캐시 열쇠로 미사용 — 글 하나의 판정이 회사 전체로 번짐 방지 | 블로그 글 하나로 네이버 전체 노랑 |
| 목록 히트 site 미저장 | 차단 목록 적중은 등록 도메인 열쇠 없이 기록 | 하위 호스트 하나로 회사 전체 오염 |
| 별칭 매칭 제한 | 두 글자 별칭은 브랜드 탐지 제외 · 도메인 질의는 이름 대조로 안 흘림 | srchdiscounts.com이 국세청 별칭 "nts"에 걸릴 뻔 (2026-08-23) |
| 공백 ≠ 근거 | RDAP "모름"·조회 실패는 사실이 아니라 공백 — 위험의 근거로 사용 금지 (프롬프트 명시) | .kr 전체가 등록일 미상 |
| 확인 불가 캐시 제외 | `unverifiable`은 판정이 아니라 실패 기록 — 기록만 남기고 캐시 조회에서 제외. 캐시하면 표 확장·페이지 복구 후에도 영영 재판정 없음 | axa.co.kr이 중위험으로 박제 (2026-08-23) |
| 공식 계정 폼 저위험 | 공식 확인된 로그인·회원가입 폼은 `LOW` — 전화번호 수집형은 공식이어도 `MEDIUM` · 변경 전 중위험 캐시는 기동 시 열쇠 해제(재판정) | 공식 사이트 회원가입에 노랑 (2026-08-24) |

### 5. 미탐 쪽 트레이드오프

오탐을 막는 대가로 감수하는 것. 대부분 "놓침"이 아니라 "확인 불가(중위험)"로 하강 — 사용자에게 선택을 넘기는 방향

| 한계 | 내용 | 완화 |
| :-- | :-- | :-- |
| 시간 예산 | 하드 리밋 9초 안 부분 정보 판정 · 느린 페이지는 3.5초·300KB에서 절단 | 페이지 없이 주소만으로는 고위험 금지 |
| `.kr` 등록일 미상 | KRNIC RDAP 미제공 — 새 도메인 신호 사용 불가 | 다른 신호(폼·브랜드 불일치·차단 목록)로 판단 |
| 브랜드 표 커버리지 | 표 밖 브랜드의 사칭은 도메인 불일치로 탐지 불가 | 표에 없음 ≠ 사칭 근거 (프롬프트 명시) · 표 확장으로 개선 |
| 차단 목록 소스 2개 | ut1 phishing·malware뿐 · 갱신 하루 1회 | 목록은 빠른 길일 뿐 — LLM 판정이 본선 |
| 강등만, 상향 없음 | `_ground`는 `HIGH`→`MEDIUM`만 — 근거 없는 저위험을 올리지 않음 | eval(`server/eval.py`)로 정확도 추적 — 차수별 결과는 [7. 차수별 측정](#7-차수별-측정) |

### 7. 차수별 측정

배포 차수별 eval (2026-08-24) — 캐시 없이(`--fresh`) · 맥 → Azure 왕복 포함. 0~5차는 42건, 6차부터 45건(로그인·회원가입 케이스 3건 추가) — "맞춤"의 분모가 다르므로 비율 병기. 차수는 대안 비교가 아니라 누적 배포 — 채택된 변경은 이후 차수에 전부 포함(현행 서버 = 5+6+7차의 합)

열 의미 — 수치는 `eval.py` 출력 그대로:

| 열 | 뜻 |
| :-- | :-- |
| 맞춤 | 기대 위험도 일치 건수/전체 — 정확도 |
